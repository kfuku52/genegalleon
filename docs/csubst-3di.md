# CSUBST 3Di analyses

Set `GG_COMMON_CSUBST_NONSYN_RECODE="3di20"` in `workflow/gg_common_params.sh`
to use structural states consistently in gene-family search, scan and summary
sites. Entrypoint overrides remain available as `csubst_nonsyn_recode` and
`csubst_site_nonsyn_recode`; the candidate summary's alphabet must match its
source scan. Full CDS input is required. Protein-only input is rejected.

Use a runtime containing CSUBST's native 3Di joint scan and portable state-cache
support. The runtime build checks the native scan options and the current
`csubst[3di]` dependency requirements. Both the Docker and native Apptainer
builds consume the shared dependency definitions. The corresponding CSUBST
changes must be installed before enabling this feature.

## Family inputs

The `iqtree_anc` stage retains its trimmed codon fit and adds `csubst.3di/` inside
`<family>_iqtree.anc.zip` when 3Di is selected. This directory contains:

- The complete pre-trimming CDS alignment restricted to the rooted tree's tips.
- A separate codon IQ-TREE fit on those full columns and that rooted topology.
- The state cache and public 3Di alignment exported by `csubst inspect`.

`csubst.input.json` records the family genetic code, full-CDS coordinate system,
relative directory and SHA-256 hashes of the inputs. Missing tips, duplicate IDs,
unequal sequence lengths and invalid codon frames fail validation. CSUBST owns
translation, gap/ambiguity handling, prediction and direct 3Di ASR.

Search, scan and both sites routes use `--full_cds_alignment_file` and the full
codon fit. They require the matching 3Di state cache, including after ZIP
extraction into another directory. Sites also forwards the family genetic code
and full fitted model. A trimmed-only bundle must be regenerated by running
`iqtree_anc` from the untrimmed CDS alignment; a missing full input is reported
with that recovery step. The new full input is registered in the existing
artifact provenance contract.

CSUBST chooses its backend, ASR mode, 3Di model and inference batching. The
current native joint path fits a uniform 3Di GTR model independently of the
codon model. N observations and exposure use the structural fit; synonymous
quantities use the codon fit. GeneGalleon's existing scan thresholds and
`--scan_pvalue_calibration none --scan_n_permutations 0` remain in force.
Analytical, parametric and bridge 3Di scan modes are outside the supported
upstream native path.

## Model resources

Workflow runtime setup defaults `CSUBST_CACHE_DIR` to
`workspace/downloads/csubst` and `HF_HOME` to
`workspace/downloads/huggingface`. Explicit environment settings take priority.
Model validation and download locks are handled by CSUBST. Weights are fetched
at runtime, not while building the image.

To prefetch the current default small backend with the current CSUBST CLI:

```bash
CSUBST_CACHE_DIR=/path/to/workspace/downloads/csubst \
  csubst download --resource esm3di-35m
```

The same command with `--no_download yes` verifies the local resource. The
ESM3Di backend keeps its required model files under the CSUBST cache directory;
other backends can also use the Hugging Face cache. Copy the corresponding
resource directories when preparing an offline execution environment.

## Report coordinates

CSUBST's raw scan `site` is zero-based. Its public `codon_site_alignment` column
is one-based and is used by GeneGalleon candidate reports. Under 3Di, that column
indexes the full alignment. The amino-acid site panel reads full CDS with the
family genetic code; the `Recoded state (3di20)` panel reads the actual CSUBST
3Di alignment. The separate alignment overview retains trimmed nucleotide
coordinates and its untrimmed mapping. Branch identities are checked against
`stat_branch` using rooted descendant-tip sets before plotting.

The existing `aa_change` database table retains `nonsyn_recode` and the generic
state columns. Its historical table/file name does not change the alphabet:
3Di letters denote structural states, not amino acids.

## Validation

Fast bundle and command tests run without model weights. The real predictor
suite is separately opt-in in a GeneGalleon container:

```bash
GG_TEST_CSUBST_3DI=1 python -m pytest -q \
  workflow/tests/test_csubst_3di_runtime.py
```

It builds actual family inputs from an eight-tip fixture, with 100 full and 90
trimmed codons, and exercises genetic codes 1 and 2, codon gaps, ambiguity and
extra-tip filtering. Search/scan outputs are
compared with direct CSUBST calls. It also tests relocated bundle reuse, offline
resource use, normal sites reports, candidate sites reports and the 3Di panel.

The GitHub tests workflow also runs this suite inside its AMD64 SIF validation
job. The shared SIF action enables it through `validate-3di: "true"`; other
callers keep model downloads opt-in. The model cache is writable under the CI
workspace and is passed explicitly through the SIF's clean environment.

See the [implementation validation record](reviews/upstream-compatibility-2026-09-11/3di/README.md)
for the tested runtime and remaining platform limits.
